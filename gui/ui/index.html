rda-ensemble

redistricting ensembles from Dave’s Redistricting data
Settings file

Holds every decision below and none of your paths, so it can be sent to someone else. A manifest.json from anyone’s output directory loads here too.

    Which state, and whose data
    What these mean
    State
    Chooses which of Dave’s Redistricting packages to use. Picking one reads its datasets automatically if the package is already downloaded; otherwise you are told what it would fetch.
    DRA version
    DRA republishes a state’s data as it is corrected. Leaving this blank uses whatever is newest, which means a run repeated next year may not match. Pin a version for anything you intend to reproduce.
    Which precincts count as neighbours
    The chain works by merging two neighbouring districts and splitting them again, so this decides where it can move at all.

    It is not quite the same question as which precincts share a border. DRA’s published graph also joins precincts across water, which sharing a border would not. That is why Alaska works only with DRA’s: worked out from the shapes alone its graph comes apart into disconnected pieces, and no chain can run.

    auto uses DRA’s when there is one and reports any disagreement with the shapes; geometry ignores it.

    Districts
    Blank draws the number the chamber actually has. Set it only to ask a deliberate what-if.
    Which population and election figures
    What a cycle is, and where these names come from

    Three population figures are needed for every run: total population, voting-age population, and citizen voting-age population. Those are what population balance and the minority metrics are computed from.

    A DRA file holds several of each, one per year, so you have to say which. Census year is a shortcut: pick a year and the three menus beside it fill in with that year’s datasets. You can then change any of them, and your choice wins. The years offered are the ones this file actually carries.

    Occasionally a year cannot choose on its own — 2020 has both a decennial count and an ACS estimate of total population, and they are not interchangeable. The year then says so and leaves the menus for you.

    Elections are different in kind. What gets scored is always a plan. But the partisan scores — efficiency gap, declination, seats bias, and the rest — cannot be computed from a plan alone: they ask how a plan would have treated the parties, which needs real votes. An election dataset supplies those votes.

    So picking two elections does not score two things. It scores every plan twice, once against each set of results, and you get two sets of partisan columns — useful when a plan looks fair under one election and not under another.

    A composite is one dataset holding an average of several real contests: E_16-20_COMP blends the 2016, 2018 and 2020 results so that no single year’s peculiarities dominate. The contests it averages are listed beside its name.

    Ticking also judge plans by each election a composite is made of adds those underlying contests as bases of their own, so you get the blend and each year separately — which shows whether a finding holds across years or rests on one of them. It does nothing unless what you picked is a composite.

    The plan the chain starts from
    What this does

    Before the chain can run it needs one valid plan to start from, drawn by splitting the precinct graph into population-balanced pieces.

    This tolerance is how balanced that first plan must be. Tighter is harder to find: too tight and the search fails rather than returning something unbalanced. 0.01 is a common starting point; North Dakota’s upper house needs it looser, and says so after about half a minute of trying.

    It is a different setting from the chain’s own tolerance below, which governs every later plan. The starting one is usually tighter.

    How the ensemble is generated
    What these mean

    The chain repeatedly merges two neighbouring districts and splits them again, keeping the result if it is balanced enough. Each accepted step is a new plan; a rejected one leaves the plan unchanged, and that repeat still counts, which is what makes the ensemble’s distribution right.

    Plans / steps
    Ask for plans and the steps are worked out: 10,000 plans sampled every 200 is two million steps. Giving steps where you meant plans quietly gives you a two-hundredth of the ensemble.
    Sample every
    Consecutive plans resemble each other, so sampling every Nth gives a more independent set. The effective sample size reported at the end says whether N was large enough.
    Variant
    cut-edges-ust unless you have a reason. The region-aware ones prefer cuts that keep counties whole; reversible samples the intended distribution exactly but rejects most proposals, so it needs far more steps.
    Population tolerance
    How far a district may sit from ideal during the chain. Looser than the starting plan’s. 0.05 is common for legislative districts and is what most published ensembles use; congressional work is often tighter.
    Chains
    Independent runs from different starting plans. One chain cannot tell you whether it explored the whole space; four can, through R-hat. They run in parallel.
    Steps between stopping points
    Runs the chain in pieces so it can be stopped between them — emptied, Stop has nowhere to act. It changes which plans you get, and is recorded, so quote it with the seed.

    The window starts it at 5000, which is under five seconds of chain even in the slowest arrangement. How long a step takes depends on how many precincts a merged pair spans, so fewer districts run slower, not faster: Michigan at 4 districts manages about 1,200 steps a second against 3,400 at 13. Chopping the chain costs nothing measurable.

    It is a fixed number rather than one timed on your machine, because the segment length changes the ensemble and a measured value would make the same settings give different results on different computers.

    Random seed
    Any number. The same seed and settings reproduce the ensemble exactly, so write it down.
    Centre the balance window on
    Almost always leave this blank. Districts divide the whole state between them, so their average population is necessarily the total divided by the number of districts — nothing here can change that. What this does change is the number the tolerance is measured from, so setting it to anything else makes the accepted range lopsided about the average that will actually occur. It is reachable because every rustrecom parameter is, not because a run normally wants it.

    These are conventions, not recommendations from rdapy: rdapy scores plans and does not generate them, so it has nothing to say about chain parameters.

    Advanced (uncommon)
    Where the results go
    What gets written, and where

    The output directory holds this run: scores.csv (one row per plan), by_district.jsonl, manifest.json, settings.json and diagnostics.json. With several chains, the per-chain files move into chain_1/ and so on.

    The second is a cache, not an output. It holds what has been downloaded from Dave’s Redistricting, one directory per state and version, and is shared by every run: a state is fetched the first time it is needed and reused thereafter. Nothing a run produces goes there, and deleting it costs only the time to download again. The Downloads tab shows what is in it.

    Neither path is saved in a settings file, because they belong to your machine rather than to the ensemble.

    Keep intermediates writes out values that would otherwise just be passed from one stage to the next. plans is the one to think about: it is the ensemble itself, it is what lets the run be extended later, and it is much the largest file.

    Also write intermediate files none by default; plans is the ensemble itself, and is what lets a run be extended later
    Extend an ensemble

    Carry an earlier run’s chain on for longer. Its settings come from its own directory, not from the Build tab — extending continues one chain, and changing its parameters halfway would make it a different one. The earlier run must have kept its plans.

    If that run was segmented the result is byte-identical to one run of the full length. If it was not, the chain is still continued — valid, since ReCom is Markov — but it will not match.

    What has been downloaded

    One directory per state and version, so pinning an older version never evicts a newer one. It adds up: every state is about 780 MB.
